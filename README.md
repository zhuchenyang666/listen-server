# listen-server

一个基于 **tkinter** 的本地后台服务管理小工具（桌面窗口，不启动任何 Web 服务）。

解决的问题：本机部署了很多服务（Spring Boot、FastAPI、Vite 前端……），端口默认都是 8080 / 8000 / 5173，时间一长记不清 **哪个端口是哪个服务**。

listen-server 做三件事：

1. **登记**：点「＋ 添加」在弹窗中注册服务（类型、启动方式、开机自启……），无需编写任何配置文件
2. **查看**：一张表列出所有服务的序号、状态、名称、类型、**实际监听的端口**、PID、资源占用、运行时长、备注、目录
3. **管理**：启动 / 停止 / 重启，查看日志，打开目录或浏览器

---

## 1. 设计原则

- **极简**：一个主窗口 + 模态子窗口
- **零 Web、零配置文件**：GUI 使用 Python 自带的 `tkinter` + `ttk`，服务登记全部在界面完成
- **少依赖**：只依赖 `psutil`（查端口与进程）
- **服务独立**：由 listen-server 启动的服务以独立进程运行，关闭窗口不会终止服务
- **Windows 优先**（终端启动、开机自启仅支持 Windows），其余功能兼容 Linux / macOS

## 2. 添加服务

点击工具栏「＋ 添加」弹出模态窗口：

| 字段 | 说明 |
| --- | --- |
| 服务类型 | 下拉选择：`jar` / `java` / `python` / `node` / `npm` / `exe` / `bat` / `powershell` / `custom`（自定义命令），不同类型显示不同输入项 |
| 服务名称 | 全局唯一 |
| 启动方式 | **无终端启动**：后台运行，输出写入日志；**终端启动**：弹出以服务名为标题的终端窗口显示输出 |
| 程序文件 | jar / exe / bat / ps1 必填，python / node 可选；选择文件后自动填充名称和工作目录 |
| 运行环境 | java / python / node / npm / powershell 可执行文件，留空使用 PATH 中的版本 |
| JVM 参数 | jar / java 类型，如 `-Xmx512m` |
| 启动参数 / 启动命令 | 原样传给服务 |
| 工作目录 | 留空时使用程序文件所在目录 |
| 环境变量 | 每行一个 `KEY=VALUE` |
| 备注 | 显示在表格中 |
| 开机自启 | 登录 Windows 后自动启动 |

底部实时显示「命令预览」，可「保存」或「保存并启动」。在表格中右键（或详情窗口中）可「编辑」「删除」。

### 端口

**端口由服务的代码编写者决定**（`application.yml`、`.env`、`vite.config`、启动参数等），listen-server 不分配端口、不注入端口相关的环境变量，添加服务时也无需填写端口。

表格中的「端口」列是运行时**从服务的进程树中实时读取**的实际监听端口：一个服务监听多个端口时全部列出（如 `8080, 8081`），未运行或尚未监听时显示 `-`。

### 开机自启

有任一服务勾选开机自启时，写入注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `listen-server` 项，登录后运行 `pythonw -m listen_server --autostart`：在后台启动所有勾选了自启、且当前未在运行的服务后退出，结果记录在 `autostart.log`。全部取消后自动删除该启动项。

> 这是「登录后自启」，不是「开机未登录时自启」；后者需要注册为 Windows 服务（需管理员权限），暂不支持。

## 3. 服务状态判定

listen-server **以进程为准** 判断服务是否在运行，再从进程树中读取监听端口：

1. **由 listen-server 启动的服务**：使用启动时记录的进程（`pid + create_time`，防止 PID 复用误判）
2. **在 IDEA、命令行等外部启动的服务**：在系统进程中识别
   - 有程序文件（jar / exe / bat / ps1 / py / js）：进程命令行中包含该文件路径（或工作目录相同且命令行包含文件名）
   - 无程序文件（npm、`python -m …`、自定义命令）：进程工作目录与登记的工作目录相同，且进程名匹配服务类型（java / python / node …）
   - 父子进程都匹配时只取父进程，停止时结束整棵进程树

| 状态 | 判定条件 | 状态圆点 |
| --- | --- | --- |
| 运行中 | 找到服务进程；端口列显示进程树实际监听的端口（尚未监听时为 `-`） | 🟢 绿色 |
| 已停止 | 未找到服务进程 | 🔴 红色 |
| 异常退出 | 由本工具启动，进程已退出且退出码 ≠ 0 | 🔴 红色 |
| 未登记 | 勾选「显示未登记端口」时，正在监听、但不属于任何登记服务进程树的端口（文字灰色） | 🟢 绿色 |

### 资源占用（CPU / 内存 / 磁盘）

口径参考 Windows 任务管理器，均为百分比，统计**监听进程及其全部子进程**之和；表头上方显示整机总占用。

| 列 | 计算方式 |
| --- | --- |
| CPU | 进程 CPU 时间占全部逻辑核心的百分比（两次刷新之间的差值） |
| 内存 | 进程工作集（RSS）占物理内存的百分比 |
| 磁盘 | 整机磁盘活动时间（PDH `\PhysicalDisk(_Total)\% Idle Time`）× 该进程 I/O 吞吐量占整机磁盘吞吐量的份额 |

> Windows 不提供单个进程的磁盘活动时间，磁盘列是按吞吐量份额估算的；进程 I/O 计数包含部分网络 I/O，份额上限按 100% 截断。

### 显示未登记端口（开关）

- **关闭**（默认）：只显示登记的服务
- **打开**：额外列出本机所有正在 LISTEN、但不属于任何登记服务的进程，排在登记服务之后；可查看、可停止（二次确认），不能启动 / 重启；系统进程（`System`、`svchost.exe`、`lsass.exe` 等）不显示也不允许结束

## 4. 界面

### 4.1 主窗口

```text
┌─ listen-server ────────────────────────────────────────────────────────────────────┐
│ [＋ 添加] │ [▶ 启动] [■ 停止] [⟳ 重启] │ [日志] [目录] │ [↻ 刷新]                    │
│ [搜索任意字段：服务名 / 端口 / PID / 类型 / 状态 / 备注 / 目录          ] ☐ 显示未登记端口 │
│                                                  8%    46%    1%                    │
│ 序号  状态      服务名         类型   端口  PID     CPU   内存   磁盘  运行时长  备注 … │
│────────────────────────────────────────────────────────────────────────────────────│
│ 1    🟢 运行中  order-service  jar  8080, 8081 15604 3.4%  6.5%   0%   1天4小时  订单服务│
│────────────────────────────────────────────────────────────────────────────────────│
│ 2    🔴 已停止  ai-api         python  -       -      -     -      -    -        AI 接口 │
│────────────────────────────────────────────────────────────────────────────────────│
│ 共 2 个服务，运行 1 个 │ 上次刷新 10:58:03                                          │
└────────────────────────────────────────────────────────────────────────────────────┘
```

- 表头深色背景；CPU / 内存 / 磁盘表头为两行：上方整机占用百分比，下方列名
- 表头与表格均有 1px 横向、竖向内边框（表头线色 `#a9b3bf`，表格线色 `#d4d4d4`）
- 每行前有序号（按当前显示顺序从 1 开始）；状态前有圆点：运行中绿色，未运行红色
- 点击 CPU / 内存 / 磁盘列头默认从高到低排序
- 行背景白 / 浅灰交替；鼠标悬浮行 `#4ca3e8` 蓝底白字；选中行 `#2a83cf` 蓝底白字（比悬浮更深，悬浮在选中行上时保持选中色）
- 鼠标在单元格上停留 0.5 秒显示完整文字提示
- 搜索框带占位提示，输入时实时过滤：任意一个单元格包含关键字即显示该行
- 点击列头排序（序号列除外），登记服务始终排在未登记端口之前
- 端口列为进程树实际监听的端口，多个端口用逗号分隔
- 每 3 秒后台刷新状态，界面不卡顿
- 快捷键：`F5` 刷新，`Ctrl+F` 搜索，`Delete` 停止选中服务

### 4.2 交互

| 操作 | 行为 |
| --- | --- |
| ＋ 添加 | 打开添加服务窗口 |
| 启动 | 按启动方式启动（服务已在运行时不可启动，包括在外部启动的） |
| 停止 | 确认后结束服务的整棵进程树（包括在外部启动的） |
| 重启 | 停止 → 等待原端口释放 → 启动 |
| 日志 / 目录 | 打开日志文件 / 工作目录 |
| 双击行 | 打开详情窗口（完整信息 + 最近 200 行日志，可启停、编辑） |
| 右键行 | 启动 / 停止 / 重启 / 编辑 / 删除 / 详情 / 打开日志 / 打开目录 / 在浏览器打开（每个监听端口一项） / 复制端口 / 复制 PID / 复制启动命令 |

支持 Ctrl / Shift 多选批量启动、停止。

### 4.3 子窗口

- 任务栏、主窗口和所有子窗口左上角统一使用 `resources/static/server.png` 图标（设置了独立的 AppUserModelID，任务栏不会显示为 Python 图标）
- 添加 / 编辑服务、服务详情均为**模态窗口**：打开期间阻塞主窗口操作，关闭后才能继续；点击模态窗口之外的区域时，提示音 + 模态窗口轻微左右抖动（幅度 ±4px，每 50ms 一步，共约 0.25 秒）
- 子窗口始终居中显示在**主窗口所在的显示器**上，并限制在该显示器工作区内
- 多显示器缩放比例不同时：启动时按鼠标所在显示器的 DPI 设置字号，并在该显示器居中打开；窗口拖到另一块显示器后自动重新计算字体、行高和列宽

## 5. 技术实现

### 5.1 模块划分

```text
src/listen_server/
├── __init__.py          # main()：启动 GUI，或 --autostart 启动自启服务
├── __main__.py          # python -m listen_server
├── config.py            # 数据目录与固定参数（字号、刷新间隔、停止超时）
├── models.py            # ServiceConfig / ServiceStatus / State / LaunchMode
├── store.py             # services.json 读写、服务类型与命令拼接
├── scanner.py           # psutil 扫描 LISTEN 端口、进程信息、类型识别、识别外部启动的服务进程
├── resources.py         # CPU / 内存 / 磁盘占用采样
├── manager.py           # 启动 / 停止 / 重启、进程树结束、运行记录、日志
├── autostart.py         # 开机自启（注册表 Run 启动项）
└── ui/
    ├── main_window.py   # 主窗口
    ├── service_dialog.py# 添加 / 编辑服务窗口
    ├── detail_window.py # 详情窗口
    ├── icon.py          # 应用图标（任务栏 / 窗口左上角）
    ├── modal.py         # 模态显示、点击窗口外抖动、子窗口定位到主窗口所在显示器
    ├── theme.py         # 字体、DPI、配色、实线边框输入框
    ├── grid_lines.py    # 表头与表格的横向 / 竖向内边框、两行表头标签
    ├── status_dots.py   # 状态列彩色圆点
    └── table_effects.py # 斑马纹、行悬浮、单元格悬浮提示
```

### 5.2 数据文件

全部位于 `~/.listen-server/`（可用环境变量 `LISTEN_SERVER_HOME` 指定其他目录）：

| 文件 | 内容 |
| --- | --- |
| `services.json` | 登记的服务（由界面维护，无需手动编辑） |
| `state.json` | 本工具启动的进程记录（`pid + create_time`，防止 PID 复用误判） |
| `logs/<服务名>.log` | 无终端启动服务的输出日志 |
| `autostart.log` | 开机自启执行记录 |

### 5.3 关键点

1. **界面不卡顿**：端口扫描与进程识别在后台线程执行，结果经 `queue.Queue` 交回主线程，用 `root.after()` 更新表格。
2. **无终端启动**：`Popen(shell=True)` + `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW | CREATE_BREAKAWAY_FROM_JOB`，输出重定向到日志；关闭 listen-server 后服务继续运行。
3. **终端启动**：`cmd /s /c "title 服务名 && 命令"` + `CREATE_NEW_CONSOLE`（不使用 `shell=True`，它会强制隐藏窗口）。
4. **停止服务**：结束整棵进程树（`npm run dev` 等子进程不残留）；系统进程和本工具自身拒绝结束；权限不足时提示以管理员身份运行。
5. **权限**：非管理员读取部分进程信息会抛 `psutil.AccessDenied`，降级显示为 `-`。

## 6. 不做的事

- 不提供 Web 页面和 HTTP 接口
- 不启动未登记的进程（未登记端口只能查看和停止）
- 不做崩溃自动重启、远程管理、开机未登录时自启

---

## 7. 运行

```powershell
uv sync
uv run listen-server-gui      # 无控制台窗口（pythonw）
uv run listen-server          # 带控制台窗口，便于看报错
```
